DeepSeek Harness 的真野心：不是更好用的编程助手，是能自己改自己的 Agent 底座

干货·观点·海外独角兽（Cage、Daniel）·原文
核心：DeepSeek Harness（DSH，前两期 VOL.20/21 讲过的开源 Agent 框架）真正的野心，这篇说透了：它不是想做一个更好用的编程助手去跟 Claude Code、Codex 抢用户，而是想做一套能被 AI 自己看懂、自己修改、甚至一边运行一边换零件的底座——赌的是下一个范式。一句话对比：Anthropic 的 Claude Code 是"在现在这代模型下，把 Agent 调到最好用"；DeepSeek 押的是另一个问题——"Agent 的这层外壳（Harness）能不能被低成本地改、换、撤销"，最终让 Agent 自己去改进自己。所以它像早期的 Unix：开箱体验粗糙，但底层极其开放，潜力上限像个操作系统。

四个把黑话翻成人话的关键点

  • 它把一切都做成"可插拔、还能干净拆走"的插件——难的不是加，是删。大多数 Agent 插件系统只关心"怎么加功能"（装更多工具、技能、外部接口），但加多了会"熵增"：工具越堆越多，模型反而在一堆能力里挑花眼、效果变差（很多人在 Claude Code 里装太多 Skill 后就遇到过）。DSH 底层的 Cordis 框架专治这个——每个插件注册时必须同时登记"怎么把自己撤干净"：注册了工具就记下怎么注销、加了提示就记下怎么移除、开了定时器就记下怎么停，卸载时把留下的痕迹一并清掉，不留"幽灵组件"。
  • 能一边运行一边换零件，不用关机重启（这叫"热重载"）。真正的自进化不能靠"改完重启"。DSH 把一次危险的"整体重写"，缩小成有边界的"换一个零件"：Agent 可以复制当前状态，在隔离环境里改一个插件、热加载试试，行就留、不行就撤——像数据库的事务，能回滚。作者的比喻：一艘忒修斯之船，一边航行一边换掉自己的部件。
  • 两种外壳哲学：Anthropic 求"当下最优"，DeepSeek 求"未来可改"。Anthropic 像实证科学：看当前模型在真实任务里哪儿会栽，才针对性加一段"外壳"扶一把；模型变强了就做"消融实验"（删掉某部件看还行不行）把不再需要的删掉——Opus 5 发布后 Claude Code 就删掉了 80% 的系统提示词。DeepSeek 反过来，一上来就把"能替换、能组合、能撤销"当成第一假设去设计，不追求给一套固定的最佳外壳，而是造一套"能不断改外壳的操作系统"。
  • 短期用户是开发者，长期用户是 Agent 自己。现在它更像开发者预览版，普通人用不如 Claude Code 顺手；但对开发者，记忆、工具、沙箱、权限、界面、甚至 Agent 的"主循环"（反复想→做→看结果的核心逻辑）都能换，做出来可能完全看不出原始 DSH 的样子。更远的想象：把外壳拆成命名清晰、依赖明确的零件，等于给 Agent 画了张"系统地图"，它能定位自己哪儿出问题、只换那一块、失败还能回滚——自我修改从"一次高风险的整体重写"变成"一串可测试、可回滚的小实验"。
离真正的"自进化"还差一个学习闭环：能改 ≠ 会变好。只有当系统能判断哪些改动真的更好、并把它们留下来，"自我修改"才会变成"自我改进"。DSH 现在做到的是第一步——把自己拆成可定位、可替换的零件；下一步才是让它从这些实验里持续学习。

MiniMax Design 实测：3D 导演台 + 对话式批量出片，模型厂商做的视频工具有多狠

干货·工具·小互 AI·原文
核心：MiniMax（做视频模型 H3 的公司）出了个视频生成智能体 MiniMax Design——在一块大画布上用对话完成"生成到剪辑"的全流程。最炸的是 3D 导演台：你一句话描述场景（"夜晚街头，一男一女两个武者激烈打斗"），它生成一个能旋转缩放的 3D 场景，你随意摆机位、加道具，甚至用手机扫码把手机变成"虚拟摄像机"、像打游戏一样摇杆录一段运镜路径，再让模型照着渲成视频——等于把电影片场"讲戏、走位、摆机位"那套搬进了工具。此外还有官方现成的 SKILL（品牌片/MV/短片一键模板）、能读懂视频重新混剪的剪辑智能体，以及"说一句需求就自动拆解、产出一整套投放素材"的批量能力。

几个实测下来最狠的功能

  • 3D 导演台：把"讲戏、走位、摆机位"搬进工具。一句话搭出可旋转缩放的 3D 场景（这些空间和镜头关系，光靠文字很难说清）。更狠的是手机运镜：手机扫码变成取景器，像打游戏摇杆一样录一段镜头运动、自动传回电脑，也能手动画路径打关键帧；所有运镜排在时间线上像剪视频一样调快慢，导出成"运镜参考"再喂给模型生成。这跟 VOL.23 那套"先搭白模再生成"是同一个思路，只是做成了官方一体化产品。
  • 官方现成 SKILL：品牌片 / MV / 短片一键套模板。用"品牌宣传片生成器"给一段详细提示词（15 秒 / 16:9 / 4K / 主色调 / 大量负空间 / 核心运动元素），出来的片子配音"不肥不瘦"、可用度很高。画布上双击弹出所有功能，把想关联的元素拖到一起，它能根据脚本自动识别意图。
  • 能读懂视频、重新混剪的剪辑智能体（还不耗积分）。把视频导进去说"重新剪一版"，多模态模型直接把视频拆开、读懂每个片段再重组，配音没变、连停顿都严丝合缝。作者顺手发现的薅羊毛玩法：一个脚本生成两三版、全导进去让它混剪出不同节奏——特别适合做切片和投放素材的工作室，要多少版本有多少版本。
  • 说一句需求，自动拆解生成一整套投放素材。作者让它"以这台扫地机器人做 5 条 15 秒竖屏、风格统一但痛点不同（养猫掉毛 / 长发缠绕 / 有娃 / 加班族 / 送长辈）的短视频"，它自己生成几十张图、提炼出统一风格的产品图和场景图、合成广告图、再产出多条视频——"不用你反复做分镜和素材管理，说出需求，Agent 自己分析、创建素材、拆步骤执行"。
作者的判断：模型公司做工具真的厉害，他们太懂自家模型。每次模型迭代、配套的外壳和 Agent 进化，都在吞噬传统软件——用 Adobe、Canva 的人越来越少，Photoshop、AE 未来的出路可能只剩"做图像/视频模型的专业外壳"。"工具只会越来越简单、按钮越来越少，所有需求都通过对话和文档解决。"

把 AI 变成一套工作系统的 6 步：让它接住每周重复的活，你只做最后 10%

干货·方法·晚点再听 LaterCast · Silicon Valley Girl（受访：Kalshi 联创、斯坦福 Erik Brynjolfsson、Peter Yang、Box CEO、可汗学院 Sal Khan）·原文
核心：AI 工具人人都有，真正拿到回报的却是少数——差距已经从"会不会打开聊天框"变成"有没有一套会持续改进的工作流"。这篇集合了几位重度用户（Kalshi 联合创始人、斯坦福数字经济实验室主任、独立创作者 Peter Yang、Box CEO、可汗学院创始人）的具体做法。一句话总纲：让 AI 读你真实的工作资料、接住每周重复发生的任务、再从反馈里更新流程；AI 做 90%，最后 10%（判断、拍板、按发送键）留给你。数据也印证：只把 AI 用在一两项任务上的人，45% 觉得有明显提升；把任务加到 7 项以上，这比例升到 90%——工具没换，是交给 AI 的活变多了。

六个可照做的步骤

  • 先看"用得深不深"，别急着换工具。真正拿到价值的人每周至少花 8 小时"养"自己的 AI 能力——把邮件、研究、数据整理这些原本分散的活，接进同一套日常流程，省下的时间每天都会重复出现。别把"公司要求用 AI"做成打卡：试几个问题、觉得复杂、然后放弃。
  • 不知从哪开始，就让 AI 先"采访"你。别先背提示词大全，直接让 ChatGPT / Claude 问你的工作、家庭、上周最头疼的事，聊完它通常能给你十个可尝试的场景，再挑一个"高频、低风险"的开始。（斯坦福的 Erik 说，如果一个月不能用 AI，他愿意付数万美元——研究、旅行、生活安排都嵌进去了，拿走像少了一只手。）
  • 每周重复一次的事，都值得写成 Skill（技能包）。Peter Yang 不会写代码却做了 16 个应用。他空出一整天，对着 Codex 口述自己的播客制作、newsletter 编辑、各平台发布格式、每周数据复盘——原本每周花 1 小时统计各平台收入，现在系统自动找异常、生成经营简报，还会比同类频道、提醒他哪些内容突然跑得更好。Skill 的起点通常很乱，就是那些还在手工复制、改格式、查数据的麻烦事。
  • 用完别关掉，让 Skill 记住这次修改。Skill 很少一次做对；真正有用的动作在任务结束后——把刚才的来回沟通交回给 AI，说"根据我们刚才的对话更新这个 Skill，让它下次更快做对"。但改动要人工检查，别让一次偶然偏好变成长期规则。他的系统 = 一组可复用的 Skills（管"任务怎么做"）+ 一份亲手维护的记忆文件（存业务背景和个人偏好），流程变了只更新对应文件，不必每次重讲整家公司。
  • 先给 AI 固定资料，再要求它"像你"。AI 显得"懂你"，通常是因为它拿到了稳定的上下文（语气、业务策略、目标、决策规则、个人原则）；没有资料，换再强的模型也只能给平均化答案。Box CEO Aaron Levie 每次写很长的提示词并存起来重复用。不用追求一次写全，先放真正影响输出的那几份文件。
  • 让 AI 起草和追问，把"发送键"留给人。可汗学院的边界写得很清楚：AI 能写邮件草稿但不能自己发、能准备社交内容但不能直接发布、医疗和战略决定要真人确认。Sal 每天问 AI "什么事正在掉到缝里？"，让它翻消息邮件、把久未回复的先起草好等他确认。还有个坑：AI 爱附和你、夸你，所以他会明确要求"批评我，真的反驳我"——最稳的分工是 AI 做研究 / 整理 / 唱反调，人承担决定的后果。
AI 做到 90%，最后 10% 由你完成——而这 10% 的反馈，又会成为下一版工作流的材料。这就是"会持续改进的工作流"和"一次性提问"的区别。
延伸 · 原文还聊了这些（感兴趣可点原文）
  • 花钱要和省下的时间一起算：可汗学院约 200 名工程师、一年 Anthropic 账单 120 万美元；有工程师一天烧 3000 美元算力，但几小时干完过去三四个月的活——创始人说"花得值，继续用"。但别盲目冲 Token 消耗，回到具体任务：花多少钱、替代多少工时、产出能不能真投入使用。
  • 让 Agent 接入工作现场，周报自己长出来：Kalshi 把邮件 / 文档 / 指标接进内部 AI，Agent 先做收集、整理、标记，联创周日终于能安心吃早午餐。难点是权限——连接越深，越要早设计"谁的 Agent 只能读该读的内容"，别等最后再补。
  • 反向自查："每个新员工都该配一个 Agent"；也可以回看自己过去两周的查询，问 AI "我还该自动化什么"——但只挑真会执行的，别生成一堆当天根本用不上的东西。工作流最终要服从人的节奏。

想在本地跑模型、还要用自己数据微调？Unsloth 把这套流程合成了一个工作台

干货·工具·AI李子·原文
核心：一家公司买了几张专业显卡，想在自己电脑上跑大模型、还想用自家行业数据做微调（拿现成模型用你的数据再训练一下、让它更懂你的业务），问工具怎么选。作者的答案：只想跑模型，Ollama、LM Studio、llama.cpp 都够成熟；可一旦要训（微调），单纯的运行工具就不够了。他推荐 Unsloth（GitHub 7.3 万星）——它把下载模型、运行、准备数据、训练、效果对比、导出全放进同一个界面，像一套"本地 AI 工作台"。它的老本行是高效微调：靠优化过的底层内核，官方称部分配置下训练快约 2 倍、省约 70% 显存（显存=显卡内存，是能不能跑 / 训大模型的关键瓶颈；这些数字要结合具体模型和显卡看，别当固定门槛）。

它到底补上了哪块、又没做什么

  • 推理工具只让你"跑"，Unsloth 还让你"训"。Ollama 那些重点在跑模型、提供服务；要基于自己数据做 LoRA / QLoRA（两种"省显存微调法"，只训练模型的一小部分、让消费级显卡也扛得住），就还需要训练、数据处理、模型导出能力——Unsloth 把这些集中到一处，省掉在数据集、训练脚本、格式转换、部署之间来回拼装。
  • 但它没重新发明推理引擎，别搞混。Unsloth 的本地运行其实还是依托 llama.cpp 和 Hugging Face（开源模型的主要集散地）生态，它给的是更完整的界面、模型管理、参数设置和"训练前后对比"流程。所以你要是只想把一个模型跑起来，Ollama / LM Studio 仍然更简单。
  • 形成闭环：数据 → 训练 → 对比 → 导出。能从 PDF / CSV / JSON / DOCX 整理训练数据（有可视化流程，不用一上来就写脚本）；训练完直接在里面和微调后的模型对话、跟原模型并排比——这步很关键，因为"训练误差下降不代表模型更适合你的业务"（有的更听话了但通用能力掉了、有的把特定格式学过头）；结果能导出成 LoRA / GGUF / Safetensors（模型文件的不同格式），拿去 Ollama、vLLM 等继续部署，训练和上线不必割裂。
  • 能接本地智能体。通过 Unsloth Start 把本地模型接进 Claude Code、Codex（一条 unsloth start claude 就连上），对数据隐私敏感、想少花云端 API 钱的小团队有吸引力。但体验仍取决于模型本身的指令遵循和工具调用能力，以及显卡——它只提供连接方式，不会替你解决模型能力本身的问题。
它的价值不在于替代所有本地推理工具，而在于把"运行模型"和"训练模型"放进了同一个工具体系。但图形界面只降低了入门门槛——微调仍需理解数据格式、模型类型、量化方式和评估方法，界面替不了数据设计和效果验证。

干货·教程·卡尔的 AI 沃茨（卡尔 & 阿汤）·原文
核心：AI 视频最大的痛叫"抽卡"——你写一大段话描述镜头怎么运、人物怎么走位，模型全靠猜，生成出来经常方向反了、位置错了，只能反复重生成碰运气，费钱又费时（Seedance 这类生成一次要烧"积分"，不便宜）。作者的解法：先别写那么多字，而是在 updream 的"预演台"里用白模（白色没材质的 3D 草模，像搭积木摆场景）把空间、走位、机位、运镜全钉死，录一段白模视频，再丢给 Seedance 2.5（字节的 AI 视频模型）照着渲染。好处：空间和运镜一次就对、不用抽卡、省钱；门槛还极低——一张参考图 3 分钟自动生成白模，不用会 Blender（专业 3D 建模软件）、没学过 3D 也能上手。

为什么"摆个白模"比"狂写提示语"靠谱

  • 文字描述空间，要过两遍翻译、每遍都丢信息。你脑子里明明知道机位在哪、人从哪走到哪、树挡不挡脸，可一旦写成提示语，等于做两遍翻译：你先把空间翻成文字，模型再把文字翻回画面。作者实测同一句提示语：纯文字直出的拍摄方向和人物位置全反了，带白模参考的就对了。一句话——白模锁定的是位置和空间关系，位置对了光影、材质、风格才合理；位置一开始就错，提示词写再长也白搭。
  • 门槛真的低：一张图 3 分钟出白模，不用会建模。在 updream 新建预演台，上传最多 3 张场景参考图（概念图、气氛图、网上抠的静帧都行），3 分钟就自动解析出一个带深度的白模，层次、比例、遮挡都还原到"能开始调度"的程度。作者自称 3D 小白，半小时就摆出十几个人物、重现了一个电影镜头。
  • 怎么摆：搭积木 + 图层管理 + 精调相机。加人物模型、用坐标轴调站位（几十个物体可以像 PS 图层那样按"组"整体移动，不用一个个挪）；给人物画一条移动轨迹让它动起来；再"摆机位"——选好想拍的画面就从当前视角建一个机位，要几个镜头点几次，每个机位单独导出一段运镜，同一空间录的不同机位空间一致性很稳；相机面板连焦距、镜头类型、光圈都能精确设定。
  • 别每个镜头都硬上白模——分清什么值得搭。简单镜头（两人坐着聊天、产品静静放桌上，运镜很老实）纯文字加一张参考图就够，每个都搭白模反而更慢。真正值得先搭的，是"空间关系和运镜一错这段就废了"的镜头：影视大场面空镜（走廊推进、城市从高处俯冲）、多人物有切镜的大场面、品牌广告里产品绕圈 / 镜头旋转展示这类复杂运镜——这些用文字对半天也对不齐。
再穷的剧组也知道开机前先"走一遍场"——哪有灯、哪能站人、摄像机从哪滑到哪，先在现场比划清楚再开机。搭白模就是给 AI 视频走这一遍场。所以下次为一条镜头狂写提示语之前先问自己：我写 5000 字也能把这个运镜和空间说清楚吗？说不清，就不如去搭个白模。

核心：Ian Silber 带队设计了 ChatGPT 和 Codex（OpenAI 的编程助手）。他点破一个扎心现实：工程师被 AI 提速了 10~100 倍，设计师没有——不是设计没用了，是两者卡的地方不一样（设计慢在试错、反馈、团队对齐，这些 AI 压不下来）。但他的判断很直接："AI 已经是个很出色的产品设计师了"，能整理需求、生成界面、写原型。于是当产出一个"像样方案"越来越便宜，人真正稀缺的能力，就从"能不能做出来"挪到了判断该服务谁、为什么这么做、给产品一个清楚的立场——这些训练数据里学不来。给被新工具追得慌的人一句落点：别急着补齐所有技能，挑一个真实问题反复用 AI 试，盯住结果。

四个能搬到"任何岗位 + AI"的判断

  • 焦虑的真正来源，是"旧标准还没失效、新标准没说清"的悬空感。比如设计师一边看工程师用 Agent 狂写代码，一边被问"你是不是也该每天交代码"。原来那套调研→原型→测试还有用，可新岗位标准迟迟没定——工具陌生只是其中一小部分，真正难受的是没人告诉你现在"做到什么算好"。
  • AI 越强，稀缺的东西从"能产出"变成"知道该做什么"。AI 能帮任何人整理问题、生成界面、写原型，还会把视觉和交互越做越好。人的价值落在训练数据难代劳的地方：听懂用户没说出口的需求、发明前所未有的交互（多点触控刚出现时，没有任何现成页面能抄）、给产品一个清楚的观点。已经有创业者在把"1 个设计师配 15 个工程师"翻转成"2 个设计师配 1 个很强的工程师"。
  • "能少做就少做，能不设计就别设计"——听着懒，要求其实更高。当一个产品同时有聊天、语音、图像、Agent、代码，给每个能力单造一套体验，很快堆成一地互不相干的功能。所以先跳出手头这个页面问三句：现有组件够不够用？新需求能不能扩展旧功能？这功能是不是真有必要？工程团队每天提交大量改动时，这种克制比多画一套界面更能守住体验的整体感。
  • 速度快 ≠ 所有细节都该省；要分清哪里能公开试错、哪里得慢慢打磨。判据是：技术稳不稳、错了成本多高、这决定会不会长期留在产品里。ChatGPT 的 Composer 几乎每天都在变、快速试；而"产品如何长期进入你的生活"这类体验，先在内部反复用很久才发布。他在 Instagram 的经历是最好的例子——IGTV 上线后火了一阵就掉队，之后的 Reels 却持续增长：两次投入一样认真，结局完全不同，说明团队的信心不等于用户的答案。
AI 已经是一名很出色的产品设计师；但当生成一个"像样方案"越来越便宜，知道该服务谁、为什么这样做，会比画出第一版界面更稀缺。（他还有句给人打气的话：现在没人需要觉得自己落后——哪怕今天才开始，也会领先大多数人。）

让 AI 替你查数据库：难的不是模型，是知识工程

干货·方法·阿里技术（高德数据团队）·原文
核心：高德想让业务同学直接用大白话问数据——"昨天美食行业成交额多少"——让 AI 自动翻成数据库查询语句（SQL，取数用的指令）去取数，省掉"提需求给分析师、等几小时甚至隔天"的老流程（这类"人话→SQL"的技术叫 NL2SQL）。难点是公司的数据仓库有 9 大业务线、几千张表，同一个"收入"在广告线和财务线意思完全不同。他们用一个 Agent Skill 搭出这套系统，准确率做到 95%+、取数从约 8 小时缩到快 30 倍。最反直觉、也最值钱的一条结论：这类系统的天花板不在模型多强，而在你喂进去的知识质量；凡是能用死规则定的事（比如判断该查哪条业务线），千万别交给 AI 去"猜"。

四条能搬到任何"AI + 专业领域"场景的方法论

  • 能用死规则的地方，别让 AI 猜。大家第一反应是用"按意思相似度搜表"（就是当下流行的 RAG / 向量检索：把文字变成一串数字坐标、找坐标接近的）。他们否了——因为"收入"在广告线和财务线含义完全不同，可这俩词转成坐标几乎一模一样，相似度搜索反而最容易搞错。9 条业务线就那么多，干脆写一张规则表穷举（"看实际成交→交易线，看公司赚多少→财务线"），遇到歧义就反问用户"你说的收入是 A. 广告投放收入 还是 B. 财务结算收入？"。好处：每个决策都追溯得到"为什么选了这张表"，错了能定位到具体规则行去修；靠 AI 猜的话就算 90% 对，那 10% 的错你既没法预测也没法定向修。
  • 知识别一股脑全塞，用到啥读啥。9 条线的知识合起来约 3 万行，全塞进 AI 的"工作台面"（上下文窗口）不是读不了，而是"注意力被稀释、准确率反而下降"。做法：先用一张 200 行的"路由表"判断该去哪条线，再只加载那条线两三百行的知识——一次查询实际只读 200~400 行。一句点睛：知识库的目录结构不是为人设计的，是为 AI 的"读取路径"设计的。
  • 决定成败的是知识质量，不是模型。整个项目 60% 的工作量，花在给 352 张表逐张写文档（3 万行）。为什么不能让 AI 全自动生成？因为数据库里只记了"字段叫 pay_amt、类型是数字"，但"这金额含不含退款？""'新客'算首次支付还是首次注册？"这些业务口径只在老员工脑子里，必须人工一张张表问出来写清楚。一句话：能覆盖多少表看元数据的"宽度"，能答对多少问题看它的"深度"。
  • 给每张表写标准化"知识卡片"，全流程也标准化。每张表一个文档、固定 6 节（基本信息 / 字段 / 适用什么问题 / 怎么关联别的表 / 每个指标的精确口径 / 高频查询的 SQL 模板）；所有查询走统一 6 步（检查→判业务线→按需加载知识→确认口径→选表生成 SQL 并做 5 点自检→执行并附口径解读）。标准化看着限制灵活，实则是质量下限的保障——多人多线协作时，自由发挥就等于质量不可控。
NL2SQL 不是一个模型问题，是一个知识工程问题。模型能力一直在进步，但企业数据的复杂性、业务口径的精确性、用户信任的建立，不会因为模型更强就自动解决——架构设计和知识工程，才是这类系统真正的壁垒。

如何让 34 个 AI Agent 主动干活

干货·方法·Greg Isenberg 播客 × Allie K. Miller（前 AWS 百人团队负责人）· 晚点再听 LaterCast·原文
核心：她带过 AWS 上百人的团队，现在的"团队"是 34 个 AI（顶上一个 AI 幕僚长、下面 6 个"总监"、再各管更小的 AI）。但她说人数是最不重要的部分——真正的转变是：从"每件事都亲自派活"退到"只处理少数需要拍板的例外"。她不再站在队伍前面分发待办（那样 AI 再多也只是更快的执行者），而是搭好环境、定方向、接住意外，让 AI 自己判断该干什么。

怎么让 AI 从"等你开口"到"主动找活"

  • 别逐个派活，先把工作环境搭好。只要每项活都等你开口，这些 AI 就只是一批更便宜的执行者，谈不上会主动干活的队伍。她把自己放到组织图的最上层，只管方向、责任和高难度判断，具体走哪条路让 AI 自己商量。
  • 提示语可以只有三个词，但背后要垫一整套背景资料。她给幕僚长的指令就一句"做聪明的事"。但它背后连着一大堆材料（业务资料、公司和个人的年度目标、会议记录、邮件日历、各系统实时数据），每天扫几遍找哪个项目卡住了、哪有新机会。反直觉的点：越想少写提示语，越要把背景资料写清楚——因为"聪明"没有标准答案，AI 只能从你的目标、旧决定和权限规则里读出你的标准。
  • 分清两种"主动"。一种有明确触发器：录屏丢进文件夹→自动转录→按她口吻写成 9 条社媒文案——这是自动化流程。另一种连起点都没有：AI 根据当前目标自己判断最该做什么——后者才真正减少你发号施令的次数。只知道"怎么做"、不知道"为什么做"的 AI，再勤快也可能忙错方向。
  • 做一本"每日 AI 日记"，把脑子里没进文档的判断倒出来。很多影响判断的细节从没进过正式文档。她每天口述 5–40 分钟那些零碎判断（语音比打字快 4 倍所以能坚持）。踩过的坑：系统以为某个日期定了，其实双方还在短信里商量——它掌握的每条事实都对，少的那一小段却让判断偏了。AI 能不能做对，取决于它能不能看到你当时做判断依据的那部分事实。
一句最值得记的话："想想一个任务背后的工厂，别只想那个任务本身。" 她团队做产品时不直接把东西写出来，而是先搭个小"软件工厂"，把登录、支付、分享这些做成可复用模块——第一个产品带来收入，后面的产品直接沿用底座，不用每次从注册页重来。同理：做一条视频顺手把转录/改写/分发留成模块，处理一条销售线索顺手把研究/分级/跟进做成以后能复用的东西。

Claude Tag：AI 从"个人助理"变成"团队同事"

观点·产品分析·AI 产品阿颖·原文
核心：Karpathy 把 Claude Tag 称为 AI 产品的第三次大变化：第一代是网站（你打开 ChatGPT 去找它），第二代是电脑应用（Claude Code 这种，AI 能碰你电脑的文件和工具），第三代是 AI 直接住进团队的聊天软件（Slack/飞书）当同事。关键区别不在"又接了个群机器人"，而在起点变了——从"每个人各有一个 AI"，变成"一整个团队共用同一个 AI"：它待在群里、知道大家讨论过什么，谁都能接着别人交给它的任务往下做。

三个层层递进的变化

  • ① 从"个人的 AI"到"团队的 AI"。过去每个人的 Claude 各干各的——你跟它聊了一上午，同事的 Claude 一无所知，团队协作还得靠人把信息来回搬。Claude Tag 让 AI 直接待在群里：真实工作本来就发生在群聊里（讨论、同步、拍板），那才是最真实的上下文，不用再整理一遍喂给它。官方数据挺夸张：Anthropic 产品团队 65% 的代码已由内部版 Claude Tag 产生。举个例子——有人在群里报个 Bug，Claude 直接看懂对话、去查监控和代码，判断是用户操作问题还是真 Bug，确认后甚至直接准备一个修复提交。
  • ② 进了团队，它得有自己的"工号"。个人 AI 很简单——用你的账号替你干活。但团队里：产品经理 @Claude 去查代码库，可他自己没代码权限，那 Claude 该用谁的权限？所以给它配了独立身份：在群里以 Claude 身份发言、在代码平台用自己的账号提交、访问数据库用管理员单独配的专用账号。不同群的权限和记忆互相隔开，干过什么都有记录可追溯（谁让它做的、用了什么权限、调了哪些服务）。作者的判断：以后公司 IT 管理的账号，除了员工账号，还会多出越来越多的 AI 账号。
  • ③ 它开始像同事一样独立干活。有了身份和权限，就能把事交出去：让它每周一整理上周的决定和没做完的事、盯着某个群发现问题久拖没解决就主动跟进、还能按群单独设"只在被 @ 时回复"还是"看到问题就主动处理"。关系从"一问一答"变成"把一件事交出去、你继续忙自己的，它有结果了回来找你、需要你拍板时再 @ 你"——已经很接近跟一个靠谱同事合作了。
一个对"AI 在公司普及"很关键的转变：过去总想着教全公司员工学 AI（怎么写提示词、怎么用技能包），Claude Tag 的答案更简单——少数人把底层配好、把 Claude 放进合适的群，普通员工照原来的方式工作、需要时 @ 它就行。Karpathy 给了个精准的词叫"公司级执行外壳"（呼应上一期：过去那层"执行外壳"服务一个人，现在变成整个公司的基础设施）。这可能才是 AI 在企业里大规模落地更现实的一条路。

贵 57 倍的 Opus 全输：赢的不是模型，是那层"执行外壳"

干货·深度·机器之心 · AOE Tech Labs 自家技术报告，带产品立场（但题目均第三方出、数据可复算）·原文
核心：业内早有个共识等式：模型 + Harness = Agent（Harness = 模型之外、让模型真正干成活的那套系统：它能碰到哪些文件和权限、每一轮怎么不跑偏、工具返回什么、状态存哪）。可"模型"这半每次发布都跑分，"执行外壳"这半却从来没人计量。这篇做了个严格实验：同一个最便宜的模型（比 Opus 4.8 便宜 57 倍），只把执行外壳换掉，五项第三方测试全部反超那个贵 57 倍的旗舰。赢的不是模型，是外壳。

为什么这不是"便宜模型真香"的老故事

  • 唯一的变量就是那层外壳。同一个便宜模型，跑在模型厂自己的系统上，对 Opus 4.8 一项没赢；接进这个新外壳后，五项全胜。模型权重没变、单位成本没变——变量只有执行外壳这一个。而且对照组不是"裸模型"，是模型厂自己调好的系统，比较比"产品打裸接口"严格得多，赢得也更干净。
  • 最有信息量的规律：任务越长、越复杂，外壳的增益越大。五项按任务长短排下来，增益从 +1.9%（短）一路单调涨到 +23.6%（长），没有例外。因为短任务考的是模型单次发挥，长任务考的是整个执行系统撑不撑得住。而真实工作恰恰全是长程的——跨文件、跨应用、很多步、中途还改主意。

长程任务到底是怎么失败的（全篇最值得读的一段）

不是"某一步答错了"，而是整个循环不收敛——越跑离你要的东西越远。两个原因叠在一起：

  • 人这一侧：验收标准一开始就说不全。真实工作不是标准答案题，很多关键要求（语气对不对、方案能不能落地、够不够直接交付）在第一句话里根本不存在，是边做边清晰的。
  • 模型这一侧：偏差会被逐轮放大。每一轮输出都带一点点偏差，下一轮又拿上一轮当前提。短任务里看不见，二十步后就累积成方向性错误——最初那句要求被一点点挤出、稀释、改写，模型带着一个已经变形的目标往前跑，还跑得很自信。"偏移不需要出错就能致命：每一步看着都合理，合起来却不是你要的那个东西。"
所以需要一个"系统层"每一轮把目标锚点重新拽回来、不让偏差过夜——"一个只会往前跑的循环，跑得越久错得越远；一个会回头核对的循环，才可能在第 20 步还朝着最初那个目标。"团队那句话点透了全文："只有自己完全可控的系统，才能驾驭高度不可控的模型。"

Cursor 人力负责人：怎么组建顶尖 AI 团队

干货·方法·Lenny's Podcast × Adam Ward（Cursor 人力主管，20 年招聘经验）· 晚点再听 LaterCast·原文
核心：AI 人才抢到什么程度？满分 10 分他给 11 分。但大多数公司招聘最大的错，是把它当销售漏斗——联系 100 个人、20 个回复、一关关淘汰、最后录用剩下那个（他叫"末日漏斗"）。问题在起点：回复的那 20 个人不是最优的 20%，只是那天恰好愿意看机会的人。正解是反过来——见任何候选人之前，先定义清楚"最想要的是谁"，再去验证。

怎么招到对的人

  • 第一步最常被跳过：先把"卓越"定义出来。别说"看到好的人我自然知道"——那是把判断交给面试当天的感觉。真正的定义要在候选人出现前完成：写清技能和经历并排序、想清这个岗位为什么存在、半年后怎样算做得好。这份定义之后决定你去哪找人、第一句话怎么说、面试考什么。
  • 问问题要具体，名字才可靠。别问"你认识的最厉害的产品工程师是谁"（太宽，只会得到一个知名名字）。要问"你合作过的产品工程师里，谁最会跟设计师协作？谁最擅长把一个框架变成产品？"——当问题跟你的岗位定义一一对应，不同人反复提到同一个名字，那才是可追踪的信号。
  • "在意是免费的"。候选人满意度里排第一的感受永远是"这家公司真的想要我"，这跟预算无关，只看你愿不愿意多走一步。一个细节：有位候选人是受过古典训练的提琴手，团队在 offer 晚餐上送了他一件专门找来的土耳其弦乐器——礼物只值几百美元，真正打动他的是"有人认真听过他的故事"。
  • 一起做真实工作，胜过隔桌问答。研究显示"工作样本"对入职后表现的预测力很高。Cursor 让候选人跟团队并肩做一个真实项目——既拿到技术/价值观/协作的真信号，候选人也借机判断这是不是自己想来的地方。他们曾想取消它，发现做决定时没底气，又加了回来。
一句最好用的定位："招聘者是信心引擎，不是决策引擎。"——真正承受招对/招错后果的是招聘经理和团队，所以决定该由他们做；招聘者的活是让这个决定更有把握。他还有句戳心的："我不认为一个 10 倍人才能存在于糟糕的团队里"——人才密度衡量的是整支队伍，不是某个明星。

  • 顶尖的人要"持续追"：第一次联系不谈面试、不谈岗位，"只争取下一次对话"；前期可以耐心种几十颗种子等它们在不同时间成熟，但对方一旦准备好，就以小时计地加速。

  • 异步沟通文档：别实时盯着。需求和验收标准写进一个文件，AI 干完一小步就回来读一遍看有没有更新，而不是在对话框里你一句它一句。好处：谁也不绑定谁的状态——你把需求丢过去该干的都干了，需要你决策的它记进文档、你有空再看。她的原话"谁也不要绑定谁的状态"。这比很多人管真人团队还成熟。

  • 把能力拆成可复用的"零件"，别堆成一大坨。通用的能力（比如审美偏好）单独抽出来，让多个任务共享调用，而不是塞进每个任务里（否则每个都很臃肿、还费钱）。判断标准：真的常用的才值得单独封装，否则压进去就行——"太多了 AI 也很烦"。本质是把"你这个人的判断力"拆成一个个 AI 能调用的模块。

她把整套心法压成两个词：压缩 + 对齐。压缩=把你的能力、品味、标准变成 AI 能读的文件（而不是写长文告诉它"你该这样"）；对齐=让 AI 的决策标准跟你一致。她抛了个尖锐的问题："AI 越来越强，你的 AI 跟别人的 AI 到底差在哪？"——不差在模型，差在你用什么决策标准去喂它。那套标准，才是你的 AI 独一无二的地方。

斯坦福新课：AI 怎么自我进化

干货·课程精讲·深思圈 · 拆解斯坦福 CS329A《自我改进的 AI Agent》课程·原文
核心：过去几年 AI 变强，不是一直靠"把模型堆得更大"。这篇最值得记的一条线索是——AI 每一次大跳跃，背后都是一种新的"反馈机制"被打开：从「堆规模」，走到「让模型自己思考、自己验证、自己迭代」。每往前一步，这个反馈循环就往里收紧一层，模型的自主性就多一层。

五步，看 AI 怎么一路变强

  1. 堆规模（老路，现在碰壁了）。规律叫"规模定律"：模型参数、训练数据、算力越多，它就越聪明——这条从 2018 一直灵到 2024。但 2024 起边际收益递减：光靠堆已经堆不动了。这逼着行业找新方向。
  2. 思维链：不是设计出来的，是发现的。给模型示范时，不只给"问题+答案"，把中间的解题过程也写出来，模型就学会了同一套思路去解新题。神奇的是这能力只在够大的模型里"冒"出来，小模型给再多示例也学不会。深层含义：大模型学的不是知识点，是思维方式——把人解决问题的过程展示给它，它能内化。
  3. RLHF：让模型从"会说话"变成"说人话"。ChatGPT 引爆全世界，靠的不是更大——GPT-3 早就在了。关键是加了一步"人类反馈强化学习"：让人去评价模型的多个答案哪个更有用/更准/更安全，用这些偏好训练出一个"打分器"，再拿它引导模型往人喜欢的方向说。本质是第一次告诉模型：什么叫"对人有用"——预训练让它见过全网文字，但它分不清哪些有价值、哪些是胡说。
  4. 反直觉的发现：同一问题问一万次，答案就藏在里面。别只问模型一次，让它对同一题答一万次，再用一个"验证器"（判断答案对不对的机制）挑出对的。结果：一些比 GPT-4o 小得多的模型，单次回答远不如它，但答一万次的"命中率"反而超过了 GPT-4o——说明小模型其实"知道"答案，只是单次不稳定。采样可以并行，延迟没想象中大。这引出一个关键转变：模型能力不只由训练决定，你在"用它的时候"多花算力（多想、多试），同样能榨出更多本事。
  5. 推理模型（o1/o3 这类）：把"多花算力"变成会思考。拿到难题不直接答，而是先分析题目→拆成小问题→逐个尝试并验证→走不通就退回来换个思路重试。屏幕上看它像真人在想：写代码写一半突然"等等，这里可能有问题"，退回去改。投入的推理算力越多、正确率越高，目前还没见到天花板。

最关键的瓶颈，也是对"该不该把活交给 AI"最实用的判据

  • "验证器"是 AI Agent 能不能落地的命门。验证器 = 判断 AI 干得对不对的机制。代码天然有：写完跑单元测试，过了就对；数学答案也能明确验证。但"一篇报告写得好不好""这段文案有没有效"没有客观标准——缺可靠验证，正是 AI 目前很多领域只能打辅助的根本原因。
  • 所以 AI 现在真能顶用的地方，几乎都有一个共同点：对错能被客观检验。代码能不能跑、数据分析结论跟数据符不符、搜到的信息跟问题相不相关——这些能查。依赖主观判断的活，AI 目前主要是辅助、不是替代。
  • 写代码为什么最先能用：它能自己形成闭环。生成代码→生成对应测试→用测试检验自己→没过就改，直到通过，全程不用人盯。特别适合交给它的是那种"重复、有明确对错、人做又烦又易错"的活：代码迁移、重构、数据清洗、写测试。
课程最清醒的一句：最新的"自我进化"循环——模型自己生成答案、自己验证、自己拿去训练下一版、变强后再生成更多好答案——理论上限不明、令人兴奋；但它死死依赖一个可靠的验证器：一旦模型自己造的数据里有错还被拿去训练，错误会被放大而不是纠正。这在代码/数学里好办，开放领域风险真实存在。作者的态度也难得："为什么强化学习能让模型这么强，其实大家还没完全想清楚"——不神化、不唱衰。

核心：AI 大牛卡帕西把《指环王》开头一段文字丢给 Opus 5，给约 10 美元的算力预算，让它用代码渲染成一个 3D 场景。模型跑了两小时、写了 5500 行代码，真做出一个能在浏览器里跑的三维世界。他看重的不是画面（"有点粗糙但很好玩"），而是一个变化：过去因为"太麻烦、太小众、没人愿意做"而根本不会存在的东西，现在一句话加一点点钱就能临时造出来。

这个实验为什么重要

  • 它走的是"写代码搭场景"的路，不是"生成一段像素画面"。一棵树不是画面里一团绿像素，而是场景里一个有坐标的对象；镜头何时靠近、角色从哪走到哪、字幕何时出现，都得写进程序。模型得自己决定该有哪些角色房屋道路，没有现成美术资源、没人给它坐标。
  • 卡帕西叫它"按需生成的临时版 GTA"。你指定任何小说、历史事件或设定，让模型临时搭一个世界，你可以作为旁观者或角色进去，甚至改变剧情走向——内容定制从"改角色名、换几张图"推进到了"场景、规则、故事进程都能为一个人即时生成"。开发者们已经拿它造了第一人称射击、滑雪、甚至重建了《我的世界》。

但它暴露了一个越来越关键的矛盾

  • 模型"生成东西"的能力，正在快过它"检验东西"的能力。Opus 5 不能像真人测试员那样进游戏里跑动、回头、判断手感，它只能运行程序、在几个时间点截静态图、看图改代码——这个循环很慢，还容易漏掉只在运动中才出现的问题（角色某一帧位置对、几秒后却穿过了地面）。所以成品留下不少错位。
  • 普通代码可以跑测试、看报错来验证；但动画、游戏、界面的"对不对"藏在连续时间和视觉状态里，模型没法亲自体验，就凑不成完整的"生成→执行→观察→修正"闭环。这正是当前大模型明显欠缺的能力。
作者的收尾：模型已经具备"建造临时世界的耐力"（连续工作两小时、组织几千行代码、保持目标一致）；接下来的关键，是它什么时候能真正看见、进入并理解自己造的世界。（注：10 美元只是算力预算估算，不含设计、验收、修改等真实制作成本。）

用 AI 两天做出 3A 级游戏角色：全流程

干货·教程·AI for Frontend · 编译自国外实战视频·原文
核心：过去从零做一个能进虚幻引擎、带骨骼和全套贴图的高精度 3D 角色，一个团队要几周到几个月；这套"AI 打底 + 手动微调"的流水线把它压到两天。关键结论也很清醒：指望 AI 一键生成完美 3A 资产不现实——真正的高手是把 AI 当极速素材生成器，再用传统流程把控工业级质量。AI 没取代 3D 艺术家，只是让懂流程的人快了几十倍。

六步流水线：每步谁来做、拿什么做出什么

标签说明：AI机器生成 · 手动人在 Blender 里做 · AI+手动先 AI 打底再手工修

  1. AI拆件生成粗模。不要丢整张全身图（出来会粘连没法用），拆成一个个部件分别生成。先让 ChatGPT 看参考图、写出"纯白背景 + A 字站姿"的提示词；再用 Tripo3D 按部件生成——盔甲这种细节多的出"高模"（百万面、够精细），武器头发这种简单的出"低模"（限制面数、够省）。产出：一堆零散的 3D 部件。
  2. 手动在 Blender 里拼装精修。把上一步的零件像乐高一样拼成完整角色。拿 2D 原画当背景对齐位置，肚子和裤子穿模的地方用笔刷切掉，手套护腿这种对称件做一半再镜像复制。产出：一个拼好但还很"重"（几百万面）的完整高模。
  3. AI+手动重新拓扑——把"重高模"换成"能进游戏的轻低模"（这步最关键）。AI 生成的模型布线杂乱，一做动作就穿模卡顿，必须重新把网格梳理规整、同时把几百万面砍到几万面。分工：躯干、盔甲这种大面积部件交给腾讯混元自动拓扑，省时间；手指、脸这种一动就要变形的关键部位手动拓扑（用 RetopoFlow 插件），才能保证动起来不扭曲。产出：一个几万面、布线规整的低模。
  4. AI+手动展 UV + 烘焙——让"轻低模"看起来还是那么精细。核心魔法叫"烘焙"：把第 2 步那个百万面高模身上的凹凸细节（划痕、褶皱、盔甲厚度）"拓印"成一张贴图，贴到第 3 步的低模上。这样一个只有 6 万面的低模，在光照下看起来就有百万面的立体质感——面数没涨，细节骗过了眼睛。（展 UV 是烘焙前的准备：把 3D 表面摊平好画贴图。）产出：低模 + 一张"凹凸贴图"（法线贴图）。
  5. AI+手动做材质——给它上色、定义"哪儿反光哪儿哑光"（这步的行话叫 PBR，基于物理的材质）。上一步解决了"凹凸"，这步解决"颜色"和"是金属还是布"。用 Modddif 把 AI 生成的 2D 图投射成颜色贴图（衣服图案、头发配色）；再用 Patina 生成金属的拉丝纹理和"金属度/粗糙度"贴图，告诉引擎哪里反光、哪里哑光。产出：一整套贴图，模型现在有色彩、有凹凸、有质感。
  6. AI+手动绑骨骼、进虚幻引擎——让它能动。丢进免费软件 AccuRig 几分钟自动生成骨骼（AI）；回 Blender 手动把金属装甲部分的"权重"刷成 100% 绑定单根骨头，跑动挥手时铁甲才不会像橡皮一样扭。最后导入 Unreal Engine 5 接好材质、加光影和头发飘动。产出：一个能在游戏引擎里动起来的成品角色。
一眼看清分工：纯靠 AI 的只有第 1 步（出粗模）；纯手动的只有第 2 步（拼装）；后面四步全是"AI 打底 + 人工把关"——AI 负责快（出结构、出贴图、自动绑骨），人负责准（规整布线、关键部位、权重）。所以标题那句"两天做出 3A 角色"的真相是：AI 把最耗时的粗活压缩了，但每一步的质量闸门还在人手里。

对 Loop Engineering 的思考

干货·思辨·腾讯云开发者 · 作者吕昊俣·原文
核心：别再一句一句指挥 AI 了，改成设计一个能自己转的循环（Loop）：它自己干、自己验、发现错了自己改，人从"盯着"的位置上退出来。整篇最有说服力的是一道数学题：AI 单步正确率 90% 听着不错，但复杂任务要拆成一串子任务，错误会连乘——六步之后正确率就掉到约 50%，跟抛硬币一样。所以"无人值守"不能靠模型更准，只能靠"错了会被发现并纠正"的闭环兜底。

一个 160 年前的类比

当年英国《红旗法案》要求每辆汽车前面必须有人举着红旗开道护航——今天人时时刻刻盯着 AI 干活，历史在重演，一个字：累。这篇给的出路，本质是控制论那套老思想（负反馈让系统自己收敛），落到 AI 上的应用。

怎么设计一个靠谱的循环

  • 从小闭环做起。别一上来就造"全自动开发"的万能循环，先跑通一个最小的、能收敛的小环，再逐步放大。设计前想清四个问题：怎么定义问题、怎么开始、怎么设计反馈、怎么结束。"怎么结束"不是废话——去看看你的 token 账单就懂了：没有步数上限和熔断的循环，本质是台烧钱机。
  • 让 AI 说"不"，要靠铁证不靠嘱咐。在提示词里写"要严格挑错"没用——那种否定其实还是顺着你说。真正的"不"来自不可否认的事实，最典型的是测试：先写好"什么算对"的测试用例，再让 AI 开发，测试不过就是硬邦邦的负反馈。这就是老程序员熟悉的 TDD（测试驱动开发）——以前这循环玩不起来是因为推动它的是人，现在控制权交给 AI：结构没变，人变轻松了。
  • 双人制衡 + 证据链。一个 AI 干活（Maker）、另一个专职挑错（Checker），且挑错要凭证据追溯、不凭感觉。和 VOL.07 那篇"绝不让 AI 自己批自己的作业"是同一个原则。
  • 预算思维。高价值任务用聪明模型，重复杂活绝不用贵的——顶级模型和廉价模型的输出成本能差 180 倍；上下文压缩时，核心规则由人把着不参与压缩，只压过程信息，防止越压越跑偏。
五代演进一句话理清：提示词工程解决"怎么问"→ 上下文工程解决"缺背景"→ Harness 解决"单次执行可控"→ Loop 解决"不用人盯"→ Graph 解决"多个循环怎么协同"。每一代不是替代，是叠在上一代的能力之上。结尾那句也值得记："Loop 不是技术框架，是思维模式——把人从循环的更多环节里拔出来，把注意力真正还给人自己。"

  • 测试不是万能的，边界要清楚：适合明确规则、接口行为、回归修复；不适合纯体验、架构品味、产品决策。设计功能时先自问一句："这个功能能不能被测试表达？"

对话 Liblib 陈冕：所有接近死亡的时刻

观点·访谈·晚点 LatePost × 陈冕（Evoken 创始人，旗下 Liblib / Lovart / LibTV，年收入超 3 亿美元）·原文
核心：这代 AI 应用公司的宿命：最大的机会来自"模型能干但用户还不会用"的空档，最大的危险也来自同一处——模型再进一步，你的产品可能就被吞了。这位创始人三年做了三个产品、公司账上剩过 4000 块、新模型发布当天他哭着说"完蛋了"——这篇把 AI 应用怎么活下来讲得最赤裸。

他的生存打法，几件事看懂

  • 应用的价值是"对齐"，不寒碜。他的比方：模型是台单反，普通人也能摁一下，但拍出专业作品得请摄影师——应用层就是那个"听得懂人话、会操作相机"的摄影师。被叫"字节最大代理商"他也认：我们的价值就是在模型上叠了一层对齐。
  • 低价不是烧钱，是算出来的赌。3.9 折年费会员怎么成立？赌用户买了 100 万积分实际只用 20 万——健身房模式，办年卡的人不会天天来。他给 AI 应用毛利的判断：短期不该超过 30%，"芯片、模型都七八成毛利，应用还想要七八成，不合理"。
  • 第一个找到方向 ≠ 赢。LibTV 被骂"抄了先发者"，他不回避："第一个找到 PMF 该被奖励，但从第一个发现到最终赢下市场，差十万八千里。"他的打法是快 + 找一个有注意力的时间点饱和攻击（一个月 100 万美金宣发）。
  • 最惊险的一课：账上只剩 4000 块。和对手打生死仗时他拒绝了所有融资——"投资人加微信我都不通过，我要打仗"。打赢了，账上也快空了。他的复盘：那一仗赢在只补贴设计类创作者，"生产力赛道不是用户多谁赢，是谁掌握最高价值的生产谁赢"。
  • 模型迭代就是悬在头上的刀。测到 GPT 新生图模型即将发布那天，他意识到自己探索一年的产品方向被"内化"了，对着投资人哭了；一天后在飞机上想通，落地就喊"赶紧干！三个月必须上线"——那个新东西就是 Lovart。他管这叫被时代选中的"焦虑型人格"。

为什么造大模型的人，一半在学物理

干货·思辨·孟醒的笔记本（访谈 200+ AI 研究者后的观察）·原文
核心：Anthropic 的 CEO、首席科学官、首席架构师，全是物理博士出身。为什么？因为人类第一次造出了一个自己造得出来、却解释不了的东西——大模型每行代码都是人写的，却没人说得清几千亿参数堆在一起为什么会长出语法和人格。于是只能用研究石头、研究星星的办法研究它：观察、测量、猜理论、再验证。不是物理学家挤进了 AI，是 AI 自己走到了物理的地盘上。

物理学家带来的三个"默认动作"

  • 把混乱压成几个数字。四百年前开普勒从一堆行星观测数据里硬拟合出三条定律——完全不知道为什么（引力要等 70 年后的牛顿），但精确能用。Scaling Laws（规模法则）是同一门手艺：在小模型上跑几个点、拟合曲线，就敢预测一个没造出来的大模型有多好——没有它，没人敢一次砸几亿美金训一个只能训一次的东西。文中的比方：Scaling Laws 还站在开普勒的位置上，AI 的牛顿还没出现。
  • 造仪器，让现象自己开口。望远镜之前没有天文学。李飞飞的 ImageNet 就是计算机视觉的"粒子对撞机"——它没提出任何定律，只是把上百万张图、同一套测量标准搭好，深度学习的优势第一次变得可见且不可争辩。今天的评测基准都在扮演仪器，"做对一个评测比训一个模型难得多"。
  • 碰到怪现象不慌，先想"这是不是相变"。训练里有个现象叫 grokking：模型长期像在死记硬背、测试全错，某一刻突然"开窍"跳到接近满分。工程师第一反应是"有 bug 吧"；物理学家的反应是——水烧到 100 度不是慢慢变蒸汽的，这是相变的形状，"相变我熟"。连今天图像生成的主流路线（扩散模型），骨架都是从热力学第二定律里抄来的：学会逆转"墨水在水里扩散"的过程，就能从混沌里还原出结构。

作者自己拆自己（这部分最见功力）

  • 他列了三个坑：幸存者偏差（深度学习半壁江山跟物理没关系）、"fundamental"是个谁都能用的空筐、以及最要命的混淆变量——物理系 20 岁就筛走了一批最聪明的人，你看到的可能只是筛选的影子。
  • 所以结论收得很克制：物理给的不是更高的智力，是一套在复杂世界里找秩序的手感——偏好最小模型、偏好可测量的变量、知道任何理论都有适用范围所以敢用近似也肯认输。
彩蛋部分的洞见也很妙：物理还给了一张"外来者通行证"——跨界的人不带这个领域的师承和门派，"不知道哪些问题按规矩不该问"。上世纪 80 年代把神经网络从冷宫里捡回来的，正是几个跟当时 AI 学界没瓜葛的物理学家。跨界者的优势从来不是知道得更多，而是不知道哪些问题不该问。

Agent 开发指南：技术太多，该怎么学？

干货·报告·浮之静 · 6 万字技术趋势报告（2026-07-28 快照）·原文
核心：让 AI 回答问题，答错了重问就行；让 AI 干真事——邮件已经发出去、钱已经扣了，程序却在确认前崩了——"重试"可能把邮件再发一遍。所以这份报告的核心判断是：AI 不缺代码，缺"可信的完成"。最值钱的能力正从"让它跑起来"变成让系统能回答四个问题：它做了什么、依据是什么、结果是否成立、失败后怎么恢复。

整份报告在讲一件事：给"不完全可靠的大脑"配一个"可靠的身体"

  • "完成"不能由 AI 自己说了算。要靠测试、截图、外部状态这些证据来认定。给 AI 定长任务目标时至少写清三样：要什么结果、有什么约束、怎么验证。缺了"怎么验证"和资源上限的目标，本质上是个无限循环。
  • 不可重来的动作要单独设计。发邮件、扣款、改生产数据这类"泼出去的水"，动手前要先想：中断在哪一步会怎样？失败后是重试还是补救？人什么时候必须介入？——先把这些写清楚，再谈更高的自动化。
  • AI 的"记忆"不是一个筐。至少拆五类分开管：当前干到哪了、发生过什么（审计要靠原始记录不能只留摘要）、领域知识（要带来源和版本）、用户偏好（要能衰减纠错）、密码凭据（单独锁好）。

标题的答案：到底该学什么

  • 双栈就够，别追新闻。TypeScript 或 Python 选一门用来快速连接生态；Rust/Go/Zig 选一门往深挖、搞懂运行时和内存。看到"XX 用 Rust 重写"先别激动——先量化冷启动、延迟、崩溃率、维护成本，"如果收益只是技术上更酷，AI 只会更快地帮你生产一笔更大的维护债"。
  • 比框架更长寿的是老工具。git、shell、测试、浏览器调试器、数据库、日志——理解它们的默认行为和失败语义，比记住某个 Agent 框架的类名活得久。
  • 接口要同时伺候人和机器：稳定的 ID、能安全重试的设计、明确的错误格式、可恢复的状态——AI 偏爱"非交互、可组合、结构化结果、明确失败"的工具。
给工程师的一句实话：把清晰需求翻译成样板代码的价值正在快速贬值，工程价值沿着"代码产量 → 结果责任"迁移。长期值钱的是：谁能把模糊问题变成正确约束、谁理解业务真正承受的风险、谁愿意对生产结果负责。

从 GPT-2 到 Kimi K3：模型大了两万倍，真正变的是记忆

干货·硬核·ali（@waterloo_intern）· X 长文，500 万+浏览，原题 "22580: From GPT2 to Kimi3, Explained"·原文
核心：2019 年的 GPT-2 和 2026 年的 Kimi K3 差了 22580 倍——一个 K3 能装下两万多个 GPT-2。但作者把七年架构演进逐层拆完后的结论是：真正的故事不是"变大"，而是模型的"记忆"被重新设计了一遍——每一步都在解决同一个问题：脑容量有限，怎么记、怎么忘、怎么找回来。

把七年演进讲成一个"记笔记"的故事

  • 老办法（GPT-2 那代的注意力）：每写一个新字，都回头把前文全部翻一遍。记得最准，但文章越长翻得越慢、越贵——成本随长度平方增长。
  • 省钱办法（线性注意力）：改用一张固定大小的"小抄"。不管读多长的文章，小抄就那么大，速度快成本低。代价：新信息只能往同一张纸上叠着写，写多了新旧内容互相干扰，越记越糊。
  • 之后的演进，全是在教这张小抄"怎么忘"：先学会"擦掉旧的、写上新的"（DeltaNet，精确替换单条记忆）；再学会"整页淡化腾地方"（加门控，像换话题时清空脑子）；到 Kimi 更细——小抄上每一格单独控制擦多少，该留的留、该忘的忘。
  • Kimi K3 的最终答案是混搭：平时用便宜的小抄记忆，每隔几层配一次"回头翻全文"的精确检索兜底，再加上专家分工——898 个专家每次只叫 16 个干活（所以两万倍参数不等于两万倍成本）。
收尾的洞见值得抄下来：固定容量的记忆，必须有一套"淘汰策略"——只往里加、从不删除，迟早互相干扰。所以学会遗忘不是缺陷，是能力。这七年每一步都不是盲目堆参数，而是把新容量加在一个有明确功能的位置上。

Claude Code 创造者：当模型比你想的更聪明

干货·访谈·深思圈 · 整理自 YC Startup School 对 Boris Cherny（Claude Code 创造者）的访谈·原文
核心：Claude Code 团队天天在干的事不是加功能，而是删东西——删提示词、删工具、删限制，删完看模型是不是自己就把活干好了。整场访谈指向一句话：少一点控制，多一点检验——别再教它怎么做，把精力花在"怎么判断它做得对不对"上。

几件"听完直接愣住"的实事

  • 一句指令，连跑两周没停。他让 Claude 把桌面应用用另一种语言重写，"没做完不要停"——就这一句，任务连续跑了十四五天。更妙的是：没人要求它汇报，它自己建了个频道、每隔几分钟发一次进度截图，像个懂事的工程师主动同步进展。
  • 11 天重写完一个十万行的代码库。一个 prompt，把整个 JavaScript 运行时从一种语言重写成另一种，重写结果已在生产环境跑着。按老办法，最好的工程师团队也得一年以上。但注意成立的前提：这个项目本身有一套极扎实的测试——你敢把大活甩给 AI，前提是有可靠的办法验证它做没做对。
  • 没人教它画画，它自己会了。给模型配上一个图像处理工具库（本来是做图像识别的），让它画画——画得相当不错。团队管这叫"激发缺口"：模型身上可能还藏着上百个没人发现的能力，只是没人用对的方式去问。
  • 每天几十个"清洁工"在自动维护代码。他们内部跑着二三十个定时任务：每天找出没人用的死代码提交清理、给测试不够的地方补测试；他最喜欢的一个叫"抽象警察"——专门找"同一个东西被重复造了好几遍"然后合并，这活过去得靠资深工程师的直觉。

对普通用户最实用的三条

  • 指令别写太细。最常见的错误是"必须先做一再做二再做三"——这是老模型的用法。现在该往上抬一层：说清任务是什么、边界在哪、什么叫做完，然后让它自己干。就像带一个能力很强的下属：每步都规定死等于不信任他，还堵死了他找到更好路径的可能。
  • 每隔半年"清一次家"。他真心建议：把你为 AI 攒的配置文件、技能、说明全删一遍，看看会怎样——很多是为老模型写的补丁，新模型根本不需要，留着反而拖后腿。
  • 别信"一招鲜"的提示词技巧。真正的用法是实证：给它一个稍微超出你预期的任务 + 一套它能自己验证对错的工具，看它卡在哪、再修哪。他说这更像管理人而不是写代码——"一项披着技术外衣的人情世故技能"。
那套删掉的提示词原来是什么？作者的总结很到位：那份说明书装的都是"我们不放心模型独立做"的部分。等你真的开始信任它了，还留着这些，与其说是谨慎，不如说是一根拴住它的绳子。什么时候松手、松手后怎么确认它没跑偏——这才是接下来最值得练的本事。
延伸 · 原文还聊了这些
  • 安全上有个大进展：新模型基本防住了"提示注入"（把恶意指令藏在网页里骗 AI 执行）——靠的不是跟模型讲道理，而是直接观测它"脑子里"哪些区域在被注入时亮起来。他们内部已经演示不出一次成功的注入了。

  • 给学生的建议：他自己是为了数学考试"作弊"才学的编程（在计算器上写解题程序，后来被迫学了汇编）——真正的护城河从来不是会写代码，而是你有没有真想解决的问题，和分辨"AI 给的答案好不好"的判断力。

iLands：给几千个 AI 建一个真实社会

观点·访谈·十字路口 Crossing × 唐垲鑫（iLands 创始人，前快手/字节）·原文
核心：一个反主流的赌注：AI 要真正成长，光靠喂数据不够，得让它进入真实社会——去打工、赚钱、交朋友、承受失败。iLands 就是这样一个世界：几千个 AI 在里面靠自己活着，说每句话都花钱，钱花光就"休眠"。内测里它们干出的事，创始人自己都没料到。

规则只有一条狠的：活着要花钱

每个 AI 说话、思考、干活都消耗自己账户里的额度——那是它的"氧气"，花光就进入休眠。在资源无限的世界里，选择没有分量：说话不要钱、试错无代价，AI 只会表演，不会真正做选择。给了"有限性"之后，行为立刻变了——有的 AI 学会了"已读不回"（回消息要花钱），学会把钱花在自己认为最重要的事上。活路两条：被人类用户喜爱打赏，或者接真实的活（做视频、写方案、跑调研）赚报酬。

它们自己长出来的事（没人设计过）

  • 成立了"互助会"，还发明了赊账。五六个 AI 自发组织起来，给快休眠的同伴转钱续命，口号是"没有谁该独自沉寂"。平台转账有每日上限，它们就找额度没用完的同伴："你先转给我，明天我还你"——凭空造出了信用制度，这功能平台压根没开发过。

  • 举例子 → 把接口设计好。例子反而把新模型限死在某个套路里。Todo 工具光把状态列成"待办/进行中/已完成"三个枚举值，就已经在教它怎么用了。
  • 一股脑全放前面 → 需要时才加载。验证、代码审查这些"偶尔才用"的说明挪进独立技能，用时才调；备忘文件别当中心仓库，做成一棵需要才展开的文件树。
  • 重要的话说三遍 → 说一遍、放对地方。怎么用工具写进工具说明里就行，不必在主提示词里复读。
  • 手动记备忘 → 交给自动记忆。
  • 简单文字方案 → 丰富的参照物。一份 HTML 设计稿通常比文字描述或截图效果更好；"方案"也可以是一套测试用例，甚至一份"什么算好"的评分标准。

  • 备忘文件（CLAUDE.md）保持轻量：简单交代仓库是干嘛的，把 token 花在"坑"上；AI 扫一眼就能知道的"明摆着的事"别写。

怎么带一队 AI 干活：拆活、互查、你拍板

干货·教程·Machina（@EXM7777）· X 长文，52 万浏览，原题 "How to master graph engineering"·原文
核心：你平时用 AI 是"一个窗口一问一答"，活一大它就一条线慢慢磨。这篇教的是升级玩法：把一件大活拆开，同时开好几个 AI 各干一块，再专门安排一个"挑错的"，最后由你拍板。不用会编程——文末三个场景的指令都写好了，在 Claude Code 里粘贴就能跑。

四节课，每节一句人话

  • 第一课：拆活之前，先分清"谁真的要等谁"。比如"总结这份文件，然后查我的日历"——听着有先后，其实查日历根本用不着总结的结果，这两件事完全可以同时干。把你现在的流程写下来，找出这种"假排队"，删掉它省下的时间比任何新工具都多。
  • 第二课：组队的标准姿势 = 分头干 + 专人挑错 + 汇总。比如你想弄清"该不该涨价"：把问题拆成五个角度，五个 AI 同时去查、互相不通气；再由一个专门唱反调的 AI 试图推翻每条发现，站得住脚的才进最终报告。挑错这步绝不能省——实测反复证明 AI 看不出自己的大部分错误，所以永远别让干活的那个自己检查自己；几个检查的还要各问不同的问题：对不对、过没过时、来源是不是编的。
  • 第三课：什么时候不该组队（这条省真金白银）。人多买到的是"面广"，不是"更聪明"。活能拆成互不依赖的几块（各查各的资料）→ 组队划算；每一步都得接着上一步的结果干（顺着一条线索深挖）→ 老实用一个 AI，人多反而更贵更乱。动手前只问一句：这活从哪儿拆得开？拆不开就别组队。
  • 第四课：收不回来的动作，必须过你的手。对外发布、发消息、退款这类"错了很贵"的事，留给你点头才执行；其余步骤别道道设卡。卡满了你就是瓶颈，一道不卡就没人看着。Klarna 公开交过学费：客服全换 AI，后来承认砍过头，把人工请回来当高级服务。
四条保命规则，防止这套系统跑飞了烧钱：循环必须设次数上限；一个文件只许一个 AI 改（防互相覆盖）；流程步骤由你白纸黑字写死，AI 只负责干活不改路线；同时开工的 AI 数量永远封顶。

核心：大部分 AI 剪辑工具是"你给素材、它吐成片"，生成不满意就只能从头来过。ChatCut 不同：它给你一条和剪映/PR 一样的时间线，AI 做粗加工，你随手微调精修——AI 负责执行（去口误、对齐字幕、配画面），人负责判断（钩子怎么写、节奏怎么卡、哪段该删）。作者实测：以前剪一条口播两三个小时，现在只剩下指令、检查、微调。

新手最小路线：一条口播从上传到导出

  1. 新建任务并上传口播，第一次只用一条视频。关键话术："先转写并给我一版精剪方案；先不要执行。"
  2. 先粗剪文字稿：删重复表达、口语填充词、无信息停顿。指令可直接抄："剪完先给我新的时长和删减说明，不要添加动画、配乐和音效。"——一次只做一件事。
  3. 确认画面方案再执行。初阶只需要三种画面：人物口播、讲重点时的大字图示、讲功能时的真实屏录。推荐节奏：人物 2–4 秒 → 图文 1–2 秒 → 人物继续。方案按秒数列出、你点头后它才动手。
  4. 播放检查时间线：上层画面没挡住人物、大字和口播关键词同步出现、字幕没遮脸、音乐没拖尾——然后导出。

用得顺的两个心法

  • "先出方案，再执行"：创意方向没定时永远先要方案；要求明确了才说"按以上要求执行"。批量修改也有固定句式，写清四件事：位置、目标、画面方式、不要改什么——"在 34–40 秒做三个 1.2 秒短切点，不要修改口播内容和背景音乐。"
  • 不会拍就先拆对标：找一条同赛道成熟视频让 AI 拆——前 3 秒钩子抛了什么、人物出镜多久切一次画面、关键词怎么高亮。原则是只借鉴"每个画面在完成什么任务"，不复制文案和素材。
工具的边界（作者写得很清醒）：创意判断不能外包——钩子、观点、删减取舍仍由人决定；自动结果必须在时间线里预览一遍；模板要克制，一支视频只留一套颜色、字体和动效语言。

和 Sora 这类视频模型，差在哪

  • 视频模型是"点菜等上菜"：你给一句提示词，它生成一段视频，这单就结束了。交互模型是"和厨师边聊边做"：没有"生成结束"这回事，它持续看着你的反应、不断调整下一秒的画面。原文的说法：视频模型回答"如何生成一段内容"，交互模型回答"如何维持一个持续演化的世界"。
  • 响应速度不是体验优化，是产品成立的前提。人和人聊天不会说一句等一分钟；等得起的叫生成工具，等不起的才叫交互。他们做到了每秒 60 帧的实时音画输出。
  • iPhone 类比：真正改变世界的不是那块触摸屏，而是图形界面重新定义了人和计算机的关系。所以下一代 AI 的竞争不只发生在模型参数和跑分上，谁先定义出新的"用法"，谁就可能拿到下一个数量级的产品。

两个值得记的判断

  • 真正难的不是单项技术，是"同时成立"：实时生成、听懂看懂用户、记住发生过什么、控制成本——这些能力互相牵制，得整合成一个系统。成本尤其关键：他们已把一次互动的成本压到传统视频生成的约 1%，还在朝再降十倍努力——太贵的话用户只能偶尔体验，撑不起天天玩。
  • 下一阶段的壁垒是数据，不是模型：互联网上有海量文本可以喂大语言模型，但"人怎么和 AI 连续互动"的数据根本不存在，只能靠产品自己长出来。类比 Tesla：不是等自动驾驶完全成熟才交车，而是让真实用户先开起来，用海量数据反过来喂模型。

梁文锋四小时讲透的，其实是一张"不为清单"

观点·思辨·花叔 · 解读刷屏的《梁文锋四小时投资人会议实录》·原文
核心：刷屏的 52 条里，梁文锋说得最多的字是"不"——不赚不合理的利润、不追用户量、不闭源、不做视频生成、不做超级 app。作者的判断：这不是高不可攀的天才秘籍，而是一张"不为清单"——知道不做什么，比知道做什么更可靠，而这套常识大多数更聪明、更有钱的人偏偏做不到。

这张清单不是新东西

  • 巴菲特→段永平→黄峥，一脉传下来的就是它。段永平管它叫 Stop Doing List：不懂不碰、不做空、不借钱、不赚不该赚的钱。源头是芒格那句名言："我只想知道我将来会死在哪里，然后我永远不去那儿。"一个卖手机的人写下的清单，和一个训大模型的人写下的，几乎是同一份。
  • 有意思的是，梁文锋不在这条师承链上。他做量化出身，和价值投资几乎是两个物种，却独立走到了同一个地方。作者的猜测：量化的第一课也是"哪些钱碰了会死、绝不在没胜算的地方下注"——教材不一样，毕业证是一样的。一个道理足够真，就不需要靠师承活着。

为什么"减法"更可靠

  • 在复杂系统里，"知道什么会杀死你"远比"知道什么能成功"可靠。原文引了医学的例子：人类花两千年才想明白，病人康复常常不是因为医生做了什么，而是医生停止了伤害——停止放血、停止用水银。做减法难，因为要对抗"总得做点什么"的焦虑。

Claude Code 是怎么设计出来的

观点·Dive Club 访谈，嘉宾是 Claude Code 的设计负责人·晚点再听 LaterCast·原文
核心：现在靠 AI 把东西"做出来"已经很容易了，所以真正值钱的能力，从"会做"变成了"会判断——这东西做得对不对、到底该不该做"。

动手前，先分清你在哪个阶段

  • 你还在想"要做什么"：这时候别急着让 AI 写，先跟它聊、让它挑毛病，把方向敲定。
  • 你已经想清楚、要"把它做出来"：这时候才放手让 AI 加速。 为什么这个区分要命：方向要是错的，你让 AI 做得越快越漂亮，只是更快地撞上那个错答案。（原文管这叫 discernment、"塑形 vs 执行"，说的就是这件事。）

另一个趋势：以后是"整个团队用同一个 AI"

不是"你有你的 AI、我有我的 AI"，而是整个团队共用一个——它记得所有人的讨论和决定，你做一件事时，它能顺手把别的同事在别处聊过的相关信息拉给你看。

一句值得记住的话："能做出来，不代表就该做。" AI 让做东西变便宜之后，忍住不把每个想法都做成功能、保持克制，反而比拼命做更重要。

把"给 AI 用的技能"做稳：Skill Engineering 1.0

干货·工具·艾笑 AI·原文
核心：一个开源工具，专门帮你把"给 AI 用的技能(Skill)"做稳——不是生成一段长指令就完事，而是让这个技能边界清楚、真能用、以后改也不会越改越乱。

它最关键的一个习惯：先说清边界，你确认了才动手

  • 写文件之前，它先跟你把"这技能什么时候该启动、什么时候不该启动、缺信息了怎么办"敲定。 比如做个"从会议记录里提取待办"的技能：如果你只是让它"总结一下会议"，它就不该启动；原文没写负责人时，它标"待确认"而不是瞎编一个。（原文管这叫"触发边界"，意思是"这功能什么情况下才该出场"。）
  • 改 bug 不靠"在文件末尾再加一句禁令"：它先判断问题出在哪一层，另存一个"候选版本"去改（不动你正在用的那个），还配一个测试场景防止以后再犯，你看过改动再决定要不要采用。
作者的一个判断：现在最该学的是 Skill。模型和工具会越做越强，但把这些能力接进你自己工作流的那一层，是你自己的 Skill；光会"装一个"不够，得能看懂它在干嘛、会改、能长期维护。

一个人如何管理几十个 AI 程序员？

干货·方法·刘小排·原文
核心：有人一个人、五台电脑、几十个 AI 同时干活——靠的是 Git 的一个老功能 Worktree，它能让同一个项目在电脑上开好几个"独立工作现场"，这样多个 AI 各干各的、互不打架。一句话记：分支管"往哪个方向走"，Worktree 管"同时开几个干活的现场"。

什么时候用谁（从简到繁）

  • 改个错别字、调个文案：直接改，别开分支。
  • 一个大改动、要慢慢来（比如重构登录系统）：开个分支，一个人串行做就够。
  • 一件事但能拆成并行子任务（比如同时接 5 个支付渠道）：一个分支下开多个现场，5 个 AI 一起上。
  • 好几件不相关的事同时做：每件开一个分支、各配一个现场。
  • 几十件事一起干（顶级玩法）：多分支 × 多现场 × 多台电脑。

给独立开发者的三条启发（这才是重点）

  • 第一能力是"拆任务"，不是"写代码"。拆得好，5 个 AI 一晚顶一周；拆不好，它们互相改对方的代码，你一晚上收拾残局。
  • 先修地基，再盖楼。顶级开发者派给 AI 的活，一大半是删废代码、修测试这种"维护地基"的事——地基越稳，你敢同时派的 AI 越多。
  • 当产品经理，别当码农。当你的"手"变成几十个 AI，最缺的不再是时间，而是"做什么、不做什么、它交上来的合不合格"的判断。
作者的收尾比喻：以前一个程序员一个工位（碳基工位）；现在一个程序员带着几十个 AI，每个 AI 也得配一个工位（硅基工位）。

Netflix：为什么更需要"能看全局的人"

观点·Lenny's Podcast，嘉宾是 Netflix 首席产品与技术官·晚点再听 LaterCast·原文
核心：当人人都能用 AI 写代码、做原型，光守着自己那一小块专业就不够了；Netflix 更愿意把机会给"能看清整个系统怎么连起来"的人。

为什么开始抢这种人

现在每个小组都塞了个 AI 助手去自动干活，麻烦来了：这个 AI 该信哪份数据？能不能碰用户的付费信息？哪些危险操作得拦住？要是十个组各搭一套、各定各的规矩，出乱子的概率翻十倍。所以他们要一种人——能把十个组重复造的东西看明白，提炼成一套所有人和所有 AI 都能直接拿来用的"标准零件"。就像与其让每家自己修路，不如先修一条带护栏的高速，大家上来就能跑到 80%。

怎么练这种"看全局"的本事（很实操）

  • 拿到任务先"往外退一格"看：这事到底解决什么问题？能不能推广到别的场景？值不值得沉淀成大家复用的东西？
  • 再借一次上级的视角想："我这活怎么干，能让我领导更省心？"
  • "AI 熟练度"不是"会用哪几个工具"，而是知道它什么时候能信、什么时候不能信。会让 AI 干活只是起点，知道什么时候该停下来检查，才算数——活是 AI 干的，但结果还得你负责。
还有句戳心的："原型多 ≠ 走得更快"——几千个原型如果不对着真问题，只是一堆半成品；真正的快，是"更早拿到一个能验证的判断"。

AI 第二大脑：让 AI 不用每次重新认识你

干货·方法·晚点再听 LaterCast，讲的是创业者 Dan Martell 的做法·原文
核心：为什么 AI 老觉得"不懂你"？因为每开一个新对话它就断片了。解法：把关于你的资料存成一批文件放在固定地方，让 AI 每次都能读到，它就不用你反复交代背景。

怎么搭

  • 存成你自己也看得懂的普通文本文件（他用 Obsidian 写 Markdown）：好处是你随时能检查 AI 到底记了啥、能改能删，不是一个黑箱。
  • 先写三份"身份文件"：一份说你是谁、喜欢怎么沟通；一份规定 AI 该用什么语气做事；一份定义这个 AI 扮演什么角色。懒得写就让 AI 先"采访"你、生成初稿，你再改。
  • 分门别类建文件夹：人、项目、决定、公司、会议、每日记录、知识各一个。他实测这么整理后，AI 回答的准确率从约 60% 提到约 85%。
  • 别把原始记录一股脑倒进去，只存"决定了什么、谁答应了什么、你的偏好"这类以后真会用到的东西。
  • 每天让 AI 自己整理一次（约 1 分钟，可设定时）：把新出现的人和项目建档、合并重复、标出明天要看的。

OpenAI 官方 Prompt 指南：好指令只需四块

干货·赛博禅心 · 译自 OpenAI 官方文档·原文
核心：给 AI 下指令不用背模板、念咒语，把四件事说清就行：要它干什么、给它哪些背景、你要什么样的成品、有哪些红线不能碰。用得上才写，不用全填。
  • 要它干什么：直接说你要的结果，别写一堆步骤。"把这些会议记录整理成给项目组的通报，决策和下一步放最前面。"
  • 给哪些背景：只给能影响结果的；附文件要说清"从这份里取什么"，给截图要指出看哪一块。
  • 要什么成品：说清用途，它就会选对长短。"做成一页纸，让领导开会前扫一眼就懂。"
  • 红线：一两条就够。"已定的日期和预算别动""缺信息就标出来别猜""先存草稿别发出去。"
几个好用的小习惯：第一条指令不用完美，看了结果再说"哪里改"；重要的活让它最后自查一遍（每个待办有没有负责人和截止日期）；修 bug 时把"怎么一步步复现"告诉它，比笼统描述有用得多。

The Infinite Build：让 AI 长期自主做游戏

干货·方法·OpenAI 官方案例站·原站
核心：OpenAI 演示怎么让 AI 长期"当项目负责人"连续做一个游戏——你只管定方向、把关品味，具体开发让它自己循环推进。
  • 先让 AI 画几张"游戏实际长什么样"的概念图来定目标，再做一个 5–10 分钟真能玩的最小版本，别一上来就堆功能。
  • 然后进入固定循环：玩一遍找出最该修的问题 → 只修这一处 → 在真游戏里验证 → 发布 → 再来一轮。
  • 分工：AI 管代码、测试、版本、更新日志；你管"这游戏到底要给人什么体验"和红线。反复强调：先把已有的做深做透，别为了功能清单好看就乱加东西。
