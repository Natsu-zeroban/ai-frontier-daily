# EDITOR.md — 终审：流水线的最后一道工序

> 写手写完、校验通过之后，发布之前，**每一期都必须过终审，不能跳过**。
> 终审交给一个**没参与写作的独立执行者**（另开一个 agent，或者无人值守时单独跑一轮），
> 只带着本文件、STYLE.md 和这一期的 HTML 进场，必要时回查原文核对事实。
> 写手很难审自己的稿：脑子里装着原文和写作过程，会把"我知道的"当成"读者知道的"，
> 把"我是怎么做的"当成"读者想知道的"。终审的价值就在于换一双眼睛。

## 0. 终审只问一个问题

**对这个读者来说，这句话合理吗？有必要吗？读起来顺吗？**

读者画像：做游戏策划，对 AI 有兴趣但不是工程师。拿手机或电脑花几分钟扫一期，
想知道"最近发生了什么值得知道的、哪些能用到我身上"。读者没读过原文，不知道这期是怎么做出来的，也不关心。

终审不是查漏补缺的清单练习，而是**以这个读者的身份把整期从头读一遍**：
每读到一处，读者会不会卡住、跳过、皱眉，或者觉得"这谁写的，好机器"？会，就改。
下面几节是判断时的参照，不是全部。没列到的情况，一律按第 0 节判断。

## 1. 三把尺子

### 1.1 合理：读者能不能理解"为什么这里有这句话"
- **制作信息不出现在正文。** 补发、抓取、篇数统计、"本期收录"、"原文是图片读不到"、写手怎么判断的……
  这些是后台信息，读者不需要知道。期号和日期已经在页面上了，导语不用再交代"这是哪天的"。
  比如导语开头写"补 9 月 20 号"，读者完全不知道"补"是什么意思。
- **立场和可信度要讲，但只讲一次。** "厂商自报""个人主观体验"放在来源行(meta)里一处就够；
  只有它会改变结论时(比如"这些数字全是厂商自报，别当定论")，才在核心里再提一句。正文、延伸块不再重复。
- **跨期呼应默认不写。** 带"VOL.xx""前几期""上期"的引用，在核心和要点里一律删掉——读者多半没读过那一期。
  真有帮助的呼应(两期合起来能得出一个新结论)，只写在本期串读里，而且要让没读过那一期的人也看得懂。
- **引用(blockquote)必须是原文里的话，并标出是谁说的。** 是写手自己总结的金句，就改写进正文或者删掉，不能装成引语。

### 1.2 必要：删掉这句，读者会失去什么
- **核心块只回答两个问题：这是什么事、为什么值得知道。** 2–4 句话，读完就能决定"要不要展开"。
  背景铺垫、数字、注意事项都往下放。
- **数字只留读者会记住、会用来做判断的。** "便宜 40 倍"有用；"每百万 token 0.042 美元""94.7% 对 93.0%"一般没用。
  一个要点里堆了三个以上的数字，基本就是在搬运原文。
- **"比如"是为了让抽象的东西落地，不是每条都要配一个。** 本来就具体的内容，硬加比如反而啰嗦。
- **重复的话删掉。** 标题、导语、核心、要点、串读讲的是同一件事的同一句话时，只在最合适的地方留一次。
- **延伸块不是回收站。** 读者可能会点进去的（试玩链接、怎么获取）才留下；"项目没有官方背书""只做了一代"这类，读者不在意就删。

### 1.3 好读：像一个懂行的朋友在跟你讲
- **去掉模板腔。** 每篇都用同一套开头和结尾（"一句话理解：""对策划的启发：""对我们的用处：""说到底""关键是"），
  读到第三篇，读者就觉得是机器在填表。用处要讲，但要融进句子里，用这一篇自己的话讲，不能贴同一个标签。
- **少用表演性的词。** "挤水分""剔掉虚火""冷静清单""泼冷水""炸了""断档领先"……原文标题可以这么写，
  摘要的叙述里不用替它渲染情绪。平实地说清事实，读者自己会判断。
- **句子短一点，一句话说一件事。** 一句话里塞了"背景 + 结论 + 比喻 + 但书"，就拆开或者删掉一部分。
  破折号、括号注释、①②③ 连用，说明这句话太挤了。
- **加粗是路标，不是装饰。** 核心块里最多一处加粗；每条要点只加粗开头那句小标题，正文里不再加粗；
  术语不靠加粗突出，靠就地解释。读者只扫加粗的部分，应该也能抓到主线。
- **固定格式不算模板腔。** "核心：""延伸""本期串读"这些是全站统一的栏目标签，属于版式，保留。
  模板腔指的是写手在句子里反复套用的说法。
- **黑话就地翻译，但只翻一次、只翻读者真的不懂的。** "Three.js（做网页 3D 的工具库）"有用；
  每个英文词都带一个括号，读起来像在看注释。
- **标题像标题，不像摘要。** 一眼能看懂、愿意点开就够了。不要用冒号把副标题、结论全塞进去。
- **导语是这一期的开场白，不是几篇核心的复述。** 2–3 句：这期几篇共同在说什么、为什么今天值得看。
  只有一篇的期，导语一句话点出看点就行，不要把核心再讲一遍。

## 2. 终审怎么做

1. **先当读者，通读整期**：导语 → 目录 → 每篇标题和核心 → 展开全文 → 串读。边读边记下卡住或别扭的地方。
2. **再当编辑，动手改**：按第 1 节逐处改，改完再从读者角度读一遍。
   - 只改表达，**不改事实**。要删减或改写某个说法时，拿不准就回查原文
     （`python skill/scripts/fetch_article.py <url>`），不能为了好读把意思改错。
   - 删掉的内容如果恰好是某个术语唯一的解释，就在这个术语剩下的第一次出现处补上一句解释。
   - 内容要不要收、收成什么形式，也由终审最后拍板：原文太薄、和读者关系太远的，降成茶点一句话；
     一天只剩茶点的，并进相邻一期，不单独成期。
3. **只改文字，不动版式骨架**（section/article 的 id、class、折叠三件套 core → detail → expand）。
   增删或拆分要点 `<li>`、删掉整个延伸块/茶点区都可以，只要 `validate_site.py` 0 FAIL。
4. **汇报时说清改了什么**：每期选 1–2 处"改前 → 改后"，再加一句为什么这么改。

## 3. 底线

- 终审的目标是"读者读得舒服、读得懂"，不是"字数越少越好"。删到读者看不懂了，就是改坏了。
  STYLE.md 的"冷读者复读"依然有效：改完要能让没读过原文的人复述出这篇讲了什么。
- 不加原文里没有的信息，不加自己的观点冒充作者的观点。
